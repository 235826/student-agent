# 第四阶段：文本与课表图片导入

入口为“导入整理”。流程为保存来源 → 排队解析 → 编辑草稿 → 逐项校对 → 保存 → 明确确认入库。任务、固定事件、每周课程可以混合导入；截止时间与事件起止时间分开保存。导入记录固定保存提交时的时区和参考时间，相对日期由模型据此解释，用户仍需核对。

## 配置兼容 Chat Completions 接口

在 `backend/.env` 设置（没有该文件时从 `.env.example` 复制，不要覆盖已有配置）：

```dotenv
SA_LLM_BASE_URL=https://你的服务商/API前缀
SA_LLM_MODEL=服务商提供的模型名
SA_LLM_API_KEY=本地密钥
SA_LLM_SUPPORTS_IMAGES=true
SA_LLM_TIMEOUT_SECONDS=60
SA_SOURCE_DIR=../data/sources
```

地址包括服务商要求的 `/v1` 等前缀，不包含 `/chat/completions`。远程必须 HTTPS，本机测试允许 HTTP。密钥只留在被 Git 忽略的 `.env`，不通过浏览器接口返回。是否支持图片由配置显式声明，需自行核对模型能力。未配置模型时解析会失败，仍可取消解析后手动添加条目，或配置后重新解析。

接口发送 `model`、`messages`、`response_format: {"type":"json_object"}`；图片以 `image_url` 的 data URL 发送。服务商必须支持 JSON 模式，以及启用时的图片输入。响应必须包含 `choices[0].message.content` JSON 字符串。请求格式参考 [Chat Completions 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。不向模型提供数据库写入或工具调用权限。

本地开发另开一个终端（与 API 使用相同环境配置）：

```bash
cd backend
uv run python -m app.workers.imports
```

Compose 的 api 和 worker 均读取可选的 `backend/.env`，数据库与图片目录覆盖为容器共享卷路径。仅修改模型配置后执行 `docker compose up -d --force-recreate api worker`。修改后端代码后需执行 `docker compose up -d --build --force-recreate api worker`，将新代码构建进镜像；仅重建容器仍会使用旧镜像。相同原文再次提交会返回已有草稿，更新服务后应在原导入记录中点击“重新解析”以获得新的识别结果。本阶段没有真实服务商配置时，只验证本地 HTTP 协议与失败分支，不能据此判断真实模型识别准确率。

## 草稿校对与边界

- 文本最多 20000 字符，补充说明最多 4000 字符；每批最多 100 个条目。图片支持单帧 PNG/JPEG/WebP，最大 8 MiB、2000 万像素。
- 模型可结合全文、补充说明、参考时间和时区推算日期时间，假设与不确定项显示在草稿中，无法确定的字段留空。evidence 用于辅助核对，可包含分散的原文片段或推定说明；后端不会因引文缺失或不连续而清空时间。格式由 Schema 校验，入库仍校验必填信息、日期范围和时间先后关系。
- 每周课程使用日期范围、星期和起止时间规则，确认后由系统展开为各周事件。模型自行理解课程上下文；未写年份等情况需核对其推定。每周规则暂不直接表达单双周或节假日，需在草稿中正确表达日期范围或确认后跳过单次课程。
- 模型生成的时长标为建议；任何编辑都会重置该项“已校对”。可以新增、移除条目、修改类型、选入或排除，编辑任务父子/依赖关系；合并内容可通过编辑保留项并移除其他项完成。
- 确认需要保存的版本号和逐项校对。任一条目验证失败，整批任务、课程、重复事件与来源关联全部回滚；夏令时不存在或有歧义的时间拒绝入库。
- 相同来源按原文内容/图片字节 SHA-256 在工作区内去重，同一批次只允许一次发布。不同截图或改写后的文本不属于相同来源，可能产生语义重复；请在预览时排除。发布幂等键冲突返回 409。
- 来源链接可以从任务或事件的“查看来源”打开。删除来源会清除原文/图片、补充说明和草稿依据，取消后台任务，保留已经创建的业务记录与来源墓碑。删除不能撤回已发送给外部服务商的材料，也不会自动清理历史备份。

## 后台与持久化

迁移 `0004` 添加 `import_sources`、`import_jobs`、`import_links`、`worker_heartbeats`。API 创建任务后返回 202，页面轮询。worker 在短事务中领取任务，以租约令牌防止过期结果覆盖取消、删除或重新领取后的状态。HTTP 请求在数据库事务之外；5xx、网络超时最多尝试 3 次，间隔 10/20 秒。429 会读取有限长度的业务错误码：模型繁忙或速率限制等待至少约 1/2 分钟并加入随机错峰，服务商的 `Retry-After` 更长时遵循该时间（最长等待 1 小时）；余额、额度和权限错误不会盲目重试。worker 重启后可领取过期租约。外部调用为至少一次语义，进程中断可能造成模型重复计费；业务发布仍为幂等。

原始图片存于私有目录，UUID 文件名不使用上传路径，先写临时文件并原子重命名再写数据库。文件系统与 SQLite 不是同一事务；worker 每小时清理超过 24 小时且无数据库引用的孤立文件。删除文件失败时通过该机制重试。API 只允许经身份认证的工作区用户读取来源。

`GET /api/v1/imports/capabilities` 返回配置可用性、图片能力声明及 worker 最近心跳，不返回密钥。没有可处理任务时也更新心跳；心跳容许一次模型请求的最长处理窗口。worker 异常仅记录固定事件名，不记录来源、响应或认证头。

备份/恢复应同时覆盖 SQLite 一致性备份和 `sources/` 目录；需要停止 API 与 worker 写入再做配套快照。既有纯数据库备份只覆盖当时的数据库，不包含后续上传的图片。

端到端测试专用启动器只接受 `e2e.db`，启动回环 HTTP 模型桩和独立 worker，图片放在 `data/e2e-sources`；生产镜像不包含测试脚本。自动化验证不调用真实外部模型。
