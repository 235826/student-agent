# 第二阶段：任务与规则基础

本阶段提供手动维护任务、课表和并行规则的完整入口，为下一阶段确定性排程提供数据。尚不生成计划，也不接入 AI 导入、提醒或长期记忆。

## 草稿与任务关系

草稿允许未填写标题，保存与发布分别操作。编辑携带版本号，过期版本拒绝覆盖；发布重新校验必填字段与关联任务，同一草稿即使并发提交或更换幂等键也只产生一个正式任务。发布后草稿不可再次编辑，正式任务独立维护。草稿操作不增加排程版本，发布正式任务时才增加。

父子关系用于组织任务，不自动表示先后依赖，也不自动汇总父任务状态。前置依赖单独设置，父级循环和依赖循环均拒绝。前置任务未完成时，不能把任务新改为进行中或已完成。已完成的历史状态不因前置任务后续变更自动改写。

删除、取消有子任务或后续依赖的任务前，页面列出影响并要求确认；不会级联删除关联任务。依赖保留并显示阻塞原因。恢复任务时重新校验关系，需要先恢复已删除的父任务和前置任务。

## 每周课表与单次变更

通过“添加课程”创建课程，再选择日期范围、星期、当地上课时间和 IANA 时区建立重复课表。范围包含首尾日期，首尾间隔最多 366 天；当前支持同日开始结束的每周课程，不支持整组课表批量修改。

生成时按当地日期逐次换算为 UTC 时间点，跨夏令时仍保持当地上课钟点。遇到不存在或有歧义的当地时间，整批拒绝，不留下部分课程。请求使用幂等键，网络重试不会重复生成。

重复课程的改单次时间、标题、地点、参加状态和并行设置存入覆盖记录，原始实例和其他周次保留。只有课程可以明确选择“本次不参加”；恢复后重新占用时间。考试不可跳过。历史普通事件不会因标题包含“课”自动识别成课程，需明确选择类型及关联课程。

## 并行规则

默认禁止重叠。通常需要双方活动接受已允许的组合，并存在用户确认的组合允许规则。任务优先使用自身设置，未设置时继承任务类型；课程实例优先使用单次设置，否则继承课程。考试及其他事件不继承关联课程的并行设置。

匹配无方向，优先级由具体到泛化：具体活动对、课程/任务类型等组合、涉及所有活动的规则。同级冲突时禁止优先。较具体的允许规则若遇到单项禁止或泛化禁止，仍需用户对两个具体活动明确勾选覆盖确认。

覆盖确认绑定当时的禁止规则版本与单项设置版本。新增或修改禁止设置后，旧确认失效，需再次确认。任务直接或间接依赖始终要求串行，不能用覆盖绕过。推断规则不作为授权。多活动检查验证每一对组合，不能只验证其中一对。跳过的课程不占个人时间，其他活动之间仍需逐对通过。

规则检查页展示每对活动的允许结果和理由；规则可以编辑或停用，记录保留。此检查只判断兼容性，不检查时段容量、截止时间或生成排程。

## 数据迁移

数据库版本由 `0001` 升至 `0002`。迁移新增字段与表，保留原有任务、事件、外键及约束。升级前使用 SQLite backup API 创建一致性备份，不能仅复制运行中的主数据库文件。

`0002` 禁止直接 downgrade，以免删除新业务数据。需要回退时先停止服务，另存升级后的数据库，再使用升级前备份配合旧版本程序恢复。原生备份在 `data/backups/`；Docker 备份在数据卷的 `/app/data/backups/`，两种运行方式的数据相互独立。
